# Chess3 — шахматный движок с двумя вариантами оценки позиции

Учебный проект (курсовая работа), в котором один и тот же поисковый алгоритм — негамакс с альфа-бета отсечением — комбинируется с двумя разными способами оценки позиции: классической эвристикой (материал плюс piece-square таблицы) и оценкой на основе обученной свёрточной нейросети. Оба варианта реализуют протокол UCI, поэтому подключаются как обычные движки к любому UCI-совместимому интерфейсу — Arena, CuteChess и подобным.

Цель проекта — пройти полный путь от классического подхода к оценке позиции до end-to-end пайплайна с нейросетью: подготовка данных, обучение модели, интеграция predicted-оценки в поиск, и сравнение получившихся движков между собой.

## Датасет

Для обучения нейросети используется `data/chessData.csv` — датасет с Kaggle, где каждая строка это позиция в FEN-нотации и её числовая оценка в сантипешках.

## Как запустить

```
pip install -r requirements.txt
```

Классический движок запускается как обычный UCI-engine — нужно указать в GUI путь к `engines/minimax/classic_uci.py`.

Нейросетевой движок запускается аналогично, через `engines/nn/nn_uci.py`, но для этого нужна уже обученная модель `chess_model.keras` — если её нет, сначала нужно прогнать обучение через `engines/nn/model.py`, которому для этого нужен `data/chessData.csv`.

## Результаты

Формального рейтингового тестирования (турнир с большим числом партий и расчётом Elo) не проводилось — движки проверялись вручную, партиями в CuteChess, друг против друга и против самого себя. По ощущениям от такого тестирования классический движок играет примерно на уровне 1300 Elo, а нейросетевой — заметно слабее, около 800. Разница, вероятнее всего, объясняется не глубиной поиска (оба движка ищут на одну и ту же глубину — 4 полухода), а качеством самой нейросетевой оценки: CNN обучалась всего 10 эпох на урезанных данных, из которых выпали все позиции с форсированным матом.

Отдельно стоит сказать про производительность нейросетевого движка: оценка каждой листовой позиции требует отдельного вызова модели через Keras, а при переборе на глубину 4 это десятки тысяч обращений к модели за один ход — это заметно медленнее классической оценки и является главным узким местом текущей реализации.
